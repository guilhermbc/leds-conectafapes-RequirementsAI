## Requisitos Funcionais (RFs)

| ID | Descrição | Prioridade | Requisitos Relacionados |
|----|-------------|----------|----------------------|
| RF001 | O sistema deve permitir a gestão e alocação de bolsas de estudo de acordo com as regras e tipos definidos. | Alta | RN001, RN002 |
| RF002 | O sistema deve permitir o registro e a gestão de dados pessoais e de contato para bolsistas e coordenadores. | Alta | RN003 |
| RF003 | O sistema deve permitir que coordenadores visualizem informações cruciais sobre seus projetos. | Alta | RF004, RF005, RF006 |
| RF004 | O sistema deve exibir uma lista de bolsistas atualmente alocados a um projeto. | Alta | RF003 |
| RF005 | O sistema deve exibir os recursos de capital e operacionais disponíveis alocados a um projeto. | Alta | RF003 |
| RF006 | O sistema deve exibir as cotas de bolsas alocadas e suas respectivas durações para um projeto. | Alta | RF003 |
| RF007 | O sistema deve permitir que coordenadores realizem realocações de bolsas dentro de seus projetos. | Alta | RF008, RF009, RN001 |
| RF008 | O sistema deve suportar a troca de uma bolsa de determinado valor por múltiplas bolsas de valores diferentes. | Alta | RF007 |
| RF009 | O sistema deve permitir que coordenadores façam ajustes nas alocações de bolsas. | Alta | RN001 |
| RF010 | O sistema deve fornecer uma funcionalidade para simular realocações de bolsas antes da finalização. | Alta | RF007, RF011, RF012 |
| RF011 | O sistema deve prever como as mudanças simuladas afetarão os valores e cotas das bolsas. | Alta | RF010 |
| RF012 | O sistema deve indicar se haverá um excedente de recursos após uma realocação simulada. | Alta | RF010 |
| RF013 | O sistema deve suportar a gestão de documentos para solicitações de bolsas e administração de projetos. | Alta | RF014, RF015, RF016, RF017 |
| RF014 | O sistema deve identificar claramente os documentos específicos exigidos para cada edital, tanto para bolsistas quanto para coordenadores. | Alta | RF013, RN002, RN003 |
| RF015 | O sistema deve permitir que os usuários carreguem os documentos exigidos. | Alta | RF013 |
| RF016 | O sistema deve exibir o status atual dos documentos carregados (ex: pendente, aprovado, rejeitado). | Alta | RF013 |
| RF017 | O sistema deve permitir a reutilização de documentos que não expiram em diferentes aplicações ou projetos. | Média | RF013, RN004 |
| RF018 | O sistema deve exibir o status atual dos processos de bolsas para os usuários. | Alta | |

## Regras de Negócio (RNs)

| ID | Descrição | Prioridade | Requisitos Relacionados |
|----|-------------|----------|----------------------|
| RN001 | Cada projeto deve ter um conjunto específico e predefinido de tipos e quantidades de bolsas que podem ser alocadas a ele. | Alta | RF001, RF007, RF009 |
| RN002 | Cada tipo de bolsa deve aderir a um conjunto específico de regras e níveis de requisitos definidos pelas FAPs. | Alta | RF001, RF014 |
| RN003 | Um bolsista deve atender a critérios de elegibilidade específicos para ser alocado a uma bolsa, incluindo certidões negativas, escolaridade mínima, idade superior a 18 anos (salvo especificação), formação/experiência relevante e residência no estado. | Alta | RF002, RF014, RF015 |
| RN004 | Apenas documentos explicitamente identificados como não perdendo a validade (ex: diploma) são elegíveis para reutilização em diferentes aplicações ou projetos. | Alta | RF017 |

## Requisitos Não Funcionais (RNFs)

| ID | Descrição | Categoria | Prioridade |
|----|-------------|----------|----------|
| RNF001 | A autenticação de usuários deve ser realizada exclusivamente através da integração com o sistema de login centralizado do governo estadual (SoulGov). | Segurança | Alta |
| RNF002 | O Portal FAPs deve se integrar com o "Sistema Administrativo (Admin)" para consumir dados essenciais, incluindo registros de editais, status de aprovação de projetos, resultados de avaliação e tipos de bolsas disponíveis. | Integração | Alta |
| RNF003 | O sistema deve permitir que coordenadores e bolsistas gerenciem suas informações de projeto e bolsa de forma autônoma. | Usabilidade | Alta |
| RNF004 | O sistema deve simplificar o registro e a gestão de dados para bolsistas e coordenadores, reduzindo a burocracia. | Usabilidade | Alta |
| RNF005 | O desenvolvimento do sistema deve considerar e aproveitar a documentação existente do sistema previamente implementado para aumentar a manutenibilidade e reduzir o esforço de desenvolvimento. | Manutenibilidade | Média |

## Perguntas e Validações

Para abordar as lacunas identificadas e garantir um entendimento abrangente para a próxima fase de desenvolvimento, por favor, forneça esclarecimentos sobre os seguintes pontos:

1.  **Requisitos de Desempenho:**
    *   Quais são os tempos de resposta máximos aceitáveis para operações críticas (ex: carregamento de detalhes do projeto, realização de uma simulação)?
    *   Qual é o número estimado de usuários concorrentes durante os horários de pico?
    *   Qual é o volume esperado de dados (ex: número de projetos, bolsas, documentos) que o sistema precisa gerenciar ao longo do tempo?

2.  **Granularidade de Papéis e Permissões de Usuário:**
    *   Poderia fornecer um detalhamento das funcionalidades específicas e permissões de acesso a dados para cada papel de usuário (Coordenadores, Bolsistas, Empreendedores)?
    *   Especificamente para Bolsistas, eles podem iniciar o upload de documentos ou apenas visualizar seu status e dados pessoais?
    *   Quais são as necessidades e interações específicas esperadas dos "Empreendedores" dentro do sistema? Eles gerenciam projetos/bolsas, ou sua interação é diferente (ex: apenas visualização de informações do programa)?

3.  **Fluxo de Trabalho de Implementação/Aprovação de Bolsas:**
    *   Poderia detalhar o fluxo de trabalho completo para a implementação de bolsas e aprovação de projetos?
    *   Quais etapas específicas são realizadas dentro do Portal FAPs e quais são tratadas pelo sistema Admin? Quais são os pontos exatos de integração e troca de dados para esses processos?

4.  **Tipos de "Ajustes" (RF009):**
    *   Além das realocações (RF007, RF008), quais outros tipos específicos de "ajustes" (RF009) um coordenador pode realizar nas alocações de bolsas ou dados do projeto dentro do sistema?

5.  **Detalhes da Sincronização de Dados:**
    *   Com que frequência os dados do sistema Admin devem ser sincronizados com o Portal FAPs? A sincronização em tempo real é necessária para algum dado, ou lotes diários/horários são aceitáveis?
    *   O fluxo de dados é estritamente unidirecional (Admin para Portal FAPs), ou o Portal FAPs também enviará dados de volta para o sistema Admin (ex: atualizações de status, novos registros, solicitações de realocação)?

6.  **Tratamento de Erros e Notificações:**
    *   Como o sistema deve lidar com erros (ex: entrada de dados inválida, operações falhas, interrupções do sistema)? Que tipo de mensagens de erro devem ser exibidas?
    *   Que tipos de notificações (ex: e-mail, alertas no aplicativo, SMS) o sistema deve fornecer aos usuários para eventos importantes (ex: mudanças de status da bolsa, rejeição de documentos, prazos próximos, aprovação de realocações)?

7.  **Auditabilidade e Registro (Logging):**
    *   Existem requisitos específicos para registrar ações do usuário, mudanças no sistema ou transações financeiras para fins de auditoria? Se sim, quais informações precisam ser registradas, por quanto tempo e quem deve ter acesso a esses registros?

8.  **Versionamento de Documentos:**
    *   Quando documentos são reutilizados ou atualizados, o sistema precisa manter versões desses documentos, permitindo que os usuários visualizem versões anteriores?

9.  **Necessidades de Relatórios:**
    *   Existem requisitos específicos de relatórios para coordenadores, administradores das FAPs (potencialmente via sistema Admin) ou outras partes interessadas com base nos dados gerenciados dentro do Portal FAPs?

10. **Requisitos de Acessibilidade:**
    *   Existem padrões de acessibilidade específicos (ex: WCAG) que o sistema precisa cumprir para garantir a usabilidade para todos os usuários, especialmente dada a sua natureza como portal governamental?

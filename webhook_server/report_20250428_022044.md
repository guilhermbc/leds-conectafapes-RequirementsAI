## Perguntas e Validações

As seguintes áreas requerem clarificação para prosseguir com o design detalhado e desenvolvimento:

**A. Funcionalidade Principal & Tecnologia:**
1.  **Entrada de Áudio:**
    *   Como os utilizadores fornecerão o áudio? (ex: Upload de ficheiro, gravação direta na app, endpoint de API?)
    *   Quais formatos de ficheiro de áudio são suportados? (ex: WAV, MP3, FLAC, OGG?)
    *   Existem limites para o tamanho ou duração do ficheiro de áudio?
2.  **Motor de Transcrição:**
    *   Qual stack tecnológica ou serviço alimenta a transcrição? (Clarificar "o pacote" - é uma biblioteca interna, ou depende de APIs externas como Google Speech-to-Text, AWS Transcribe, API do YouTube, Gemini, Whisper, etc.?)
    *   A escolha da tecnologia impõe limitações (ex: custo, limites de taxa, implicações de privacidade de dados)?
3.  **Saída:**
    *   Qual é o formato necessário para a saída de texto? (ex: Texto simples (.txt), texto estruturado (JSON), documento (.docx), legendas (.srt/.vtt), incluir timestamps?)
    *   Como a saída é entregue/acedida? (ex: Exibida no ecrã, ficheiro para download, resposta de API?)

**B. Qualidade & Desempenho:**
4.  **Precisão (RNF001):**
    *   Qual é o nível de precisão alvo? (ex: Definir usando Taxa de Erro de Palavra (WER) ou outra métrica).
    *   Quais variações o sistema deve suportar? (ex: Diferentes idiomas, sotaques, níveis de ruído de fundo, múltiplos falantes no mesmo áudio?) Especificar o que está dentro/fora do escopo para a versão inicial.
5.  **Desempenho:**
    *   Qual é o tempo máximo esperado para a transcrição? (ex: Tempo real, quase tempo real, X minutos por Y minutos de áudio?) Definir isto para cenários típicos de "teste".
6.  **Disponibilidade/Confiabilidade (RNF003):**
    *   Quantificar "operacional e responsivo". (ex: Percentagem de uptime alvo durante períodos de teste? Tempo máximo de resposta para interações de UI relacionadas com testes?)

**C. Experiência do Utilizador & Tratamento de Erros:**
7.  **Usabilidade (RNF002 & Escopo):**
    *   Definir os passos específicos envolvidos no "teste simples". O que constitui um teste bem-sucedido da perspetiva do utilizador?
    *   Além do papel de "testador", existem outros papéis de utilizador antecipados? (ex: Utilizador final, Administrador?) Quais são as suas necessidades específicas em relação à usabilidade?
8.  **Tratamento de Erros:**
    *   Como o sistema deve responder se a transcrição falhar? (ex: Formato de áudio inválido, ficheiro corrompido, timeout de processamento, erro de API?)
    *   Que feedback específico deve ser fornecido ao utilizador em caso de erros?

**D. Operacional & Conformidade:**
9.  **Regras de Negócio (Lacuna RN):**
    *   Existem restrições operacionais, políticas ou fluxos de trabalho? (ex: Períodos de retenção de dados para áudio/transcrições, quotas de uso, passos específicos de fluxo de trabalho necessários antes/depois da transcrição?)
10. **Segurança & Privacidade:**
    *   Quais são os requisitos de segurança de dados? (ex: Encriptação em repouso/em trânsito, controlos de acesso?)
    *   Existem regulamentos de privacidade específicos a cumprir? (ex: GDPR, LGPD, HIPAA?) Como os dados do utilizador (áudio, transcrições) devem ser tratados para garantir a conformidade?

## Dúvidas e Validações Pendentes

Os requisitos acima foram refinados com base na análise inicial e nas perguntas levantadas. No entanto, os seguintes pontos ainda requerem **confirmação ou detalhamento** por parte dos stakeholders para finalizar o escopo e garantir a precisão:

1.  **Escopo RF028:** Confirmar se a submissão de *novas propostas de projeto* estará neste portal ou permanecerá em outro sistema.
2.  **Fluxo de Remanejamento (RF014/RN008):** A efetivação do remanejamento no portal dispara uma *solicitação* para o Admin FAPESP, ou só é possível efetivar no portal *após* aprovação no Admin FAPESP?
3.  **Fluxo de Validação de Documentos (RF018/RN008):**
    *   Quem valida os documentos: Coordenador (portal), Analista FAPESP (Admin), ou ambos?
    *   A validação é por documento ou apenas do conjunto completo?
    *   A ativação da bolsa no Admin FAPESP (refletida em RF027) é automática pós-validação ou requer ação manual no Admin?
4.  **Validade de Documentos (RF021/RN006):**
    *   Listar exemplos concretos de documentos com e sem validade.
    *   Definir a ação exata do sistema quando um documento obrigatório de bolsista ativo expira (bloqueio, notificação para quem, suspensão?).
5.  **Consulta de Regras (RF024):** Definir o formato preferido: links para PDFs/externos ou conteúdo estruturado/pesquisável no portal?
6.  **Perfis de Usuário:** Existem outros perfis além de Coordenador e Bolsista (ex: Admin FAPESP, Pesquisador sem projeto)? Se sim, quais suas permissões específicas? (Pode gerar novos RFs).
7.  **Notificações (RF_NOTIF):** Confirmar os mecanismos preferidos (e-mail, portal, ambos) e os eventos específicos que devem gerar notificações.
8.  **Dados Bancários (RF_BANK/RN008):** Quem insere/atualiza os dados bancários? Será neste portal, no Admin FAPESP, ou outra fonte? O portal permitirá edição ou apenas visualização?
9.  **Métricas Não Funcionais (RNF005/RNF007):** Definir metas quantitativas para usuários simultâneos, volume de dados e tempos de resposta máximos.
10. **Tratamento de Erros (RNF_ERR):** Detalhar o comportamento esperado e as mensagens para cenários de erro específicos (falha de integração, inelegibilidade, upload inválido, rejeição no Admin).
11. **Migração de Dados (RF_MIG):** Confirmar a necessidade de migração e detalhar quais dados de quais sistemas legados.
12. **Auditoria (RNF_AUDIT):** Confirmar a necessidade e o nível de detalhe requerido para os logs de auditoria.Com as respostas a estes pontos, os requisitos poderão ser finalizados e detalhados para guiar o desenvolvimento.

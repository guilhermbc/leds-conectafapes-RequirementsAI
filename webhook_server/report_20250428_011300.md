## Perguntas e Validações

A lista de perguntas abaixo precisa ser respondida para finalizar os detalhes dos requisitos antes do desenvolvimento:

1.  **Definição de Escopo (RF019):** Confirmar se a submissão de *propostas iniciais de projetos* pelo portal está no escopo do Produto Mínimo Viável (MVP) / primeira versão, ou planejada para uma fase futura.
2.  **Escopo de "Outros Públicos" (RF016):** Especificar os tipos exatos de usuários além de Coordenadores e Bolsistas (ex: Empreendedores). Quais ações específicas eles devem realizar (cadastro, consulta de status, upload de documentos, etc.)? Essas ações estão ligadas apenas a programas específicos (como Centelha) ou são mais amplas?
3.  **Fluxo de Validação e Reutilização de Documentos (RF008, RF010, RN009):**
    *   Quem é responsável por validar os documentos submetidos?
    *   A validação é feita no Portal FAPs ou no sistema FAPs Admin?
    *   Como o Portal deve exibir o status do documento (pendente, aprovado, rejeitado)?
    *   Como o usuário é notificado do resultado da validação?
    *   Como exatamente o sistema permite a reutilização de documentos *validados* e não expirados? O usuário seleciona de uma lista?
4.  **Validade e Atualização de Documentos (RF011, RN008):**
    *   Quais são os períodos de validade específicos ou frequências de atualização para documentos que expiram (ex: comprovante de residência)? Isso varia por tipo de documento?
    *   Com quanta antecedência o sistema deve avisar os usuários sobre documentos expirando?
5.  **Regras de Remanejamento de Bolsas (RF012, RF013, RN010):** Fornecer as regras específicas e detalhadas que governam o remanejamento. Quais são as restrições relativas a limites orçamentários, trocas permitidas entre tipos de bolsa/projetos e quaisquer restrições específicas do edital?
6.  **Parâmetros da Ferramenta de Simulação (RF013, RF014):**
    *   Quais entradas/parâmetros específicos os Coordenadores devem poder ajustar na ferramenta de simulação (ex: trocar Bolsistas, mudar tipos de bolsa, ajustar datas de início)?
    *   Quais saídas/impactos específicos a simulação deve exibir (ex: mudanças no orçamento, uso de cotas, avisos de conformidade)?
7.  **Detalhes da Integração com Sistema Admin (RF017, RF018, RN012, RNF004):**
    *   Qual a frequência necessária para sincronização de dados entre o sistema Admin e o Portal (ex: tempo real, hora em hora, diário)?
    *   Qual o comportamento esperado do Portal se o sistema Admin estiver temporariamente indisponível durante operações de busca/atualização de dados? Deve exibir dados em cache, mostrar um erro ou tentar novamente?
8.  **Exceções à Regra de Residência (RN006):** Existem exceções definidas para a regra de que Bolsistas devem residir no estado? Se sim, quais são?
9.  **Fluxos de Trabalho Principais:**
    *   Descrever o fluxo passo a passo para a *implementação da bolsa*, começando com o Coordenador iniciando o processo (RF006), incluindo ações do Bolsista (RF007, RF008), validação de documentos, alocação pelo Coordenador (RF012) e confirmação/ativação final. Existem etapas de aprovação específicas neste fluxo?
    *   Existem outros fluxos críticos que precisam de definição detalhada (ex: cadastro do Bolsista, atualização de documentos)?
10. **Tratamento de Erros e Notificações:**
    *   Como o sistema deve tratar e reportar erros aos usuários (ex: falha no login, entrada de dados inválida, falha no upload de documento, violações de regras de alocação)?    *   Quais notificações específicas ao usuário são necessárias (ex: confirmação de submissão bem-sucedida, resultados da validação de documentos, avisos de expiração de documentos (RF011), mudanças de status da bolsa (RF015), confirmações de alocação)? Como devem ser entregues (ex: mensagens no aplicativo, e-mail)?
11. **Dados de Cadastro do Bolsista (RF007):** Quais campos de dados específicos são necessários durante o cadastro/atualização do perfil do Bolsista? Essa informação é padrão ou varia com base no edital ou tipo de bolsa?
12. **Definição de Metas para RNFs (RNF008, RNF009, RNF010):** Para finalizar estes RNFs, precisamos de metas específicas. Podem fornecer:
    *   **Desempenho:** Tempos de resposta esperados para ações chave, número previsto de usuários simultâneos, volumes estimados de dados (usuários, projetos, documentos).
    *   **Disponibilidade:** Percentual de uptime necessário (ex: 99,5%) e janelas de manutenção permitidas.
    *   **Acessibilidade:** Padrão e nível alvo (ex: WCAG 2.1 Nível AA). Isso é um requisito legal?---
